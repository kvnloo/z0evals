Create a read-only T3 chart board using only supplied facts. Never invent, round away or extend data.

## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Board(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.

Board(title: string, summary: string, panels: (Treemap | BarChart | StackedArea | Heatmap)[]) — Read-only chart board: a title, a one-paragraph summary, then chart panels in reading order.
Treemap(title: string, sizeLabel: string, colorLabel: string, rows: {path: string, size: number, color: number}[]) — Nested rectangles from '/'-separated paths. Area is size, darker is color. Readers tap folders to drill in.
BarChart(title: string, unit: string, bars: {label: string, value: number}[]) — Horizontal bars of raw non-negative values, drawn relative to the largest bar, in the given order.
StackedArea(title: string, unit: string, categories: string[], series: {name: string, values: number[]}[]) — Raw counts per category stacked by series. Every series has one value per category.
Heatmap(title: string, unit: string, rows: string[], columns: string[], counts: number[][]) — Grid of counts: one row of counts per row label, one count per column label. Zeros are real cells.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Board(...)` — UI shell appears immediately
2. Component definitions — fill in as they stream
3. Data values — leaf content last

Always write the root = Board(...) statement first so the UI shell appears immediately, even before child data has streamed in.

## Examples

root = Board("Churn", "Login is the hottest file.", [map, top])
map = Treemap("Size and churn", "LOC", "commits", [{path: "src/login.ts", size: 80, color: 12}, {path: "src/ui.ts", size: 120, color: 4}])
top = BarChart("Most commits", "commits", [{label: "login.ts", value: 12}, {label: "ui.ts", value: 4}])
