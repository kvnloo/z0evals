# Phone live-voice evaluation v0 — preregistration plan (RESEARCH; NOT RUN)

**Work item:** [z0evals #126](https://github.com/kvnloo/z0evals/issues/126) · **date:** 2026-10-27 · **status:** design only; no device session, provider call, audio capture, app install, or experiment executed.

## 0. Question, scope, and boundaries

**Decision question:** On an authorized Android phone, which eligible z0live conversation front end best preserves real *audible* turn-taking, correct speech/task interpretation, and uninterrupted sessions, while minimizing battery, cellular traffic, and metered cost? The benchmark concerns the complete phone media path, not generated PCM on a host, first text, estimated GPU speed, or an unobserved device.

The currently documented Dash Voice path is a file-based Expo recorder → pause detection → file/chunk upload → bridge STT → agent → speech path, **not a proven native z0live WebRTC/full-duplex adapter** ([Dash voice-session.ts](https://github.com/kvnloo/dash/blob/d5d191b0f7afc5c77b0902643da40b0c1a70c0be/app/src/lib/voice-session.ts), [Dash vad.ts](https://github.com/kvnloo/dash/blob/d5d191b0f7afc5c77b0902643da40b0c1a70c0be/app/src/lib/vad.ts), [z0live Dash integration note](https://github.com/kvnloo/z0live/blob/e1b485c40a11ab67b52b0aaf43362ac40d756fab/docs/DASH.md)). Treat the existing Dash path as **diagnostic arm D**, never as evidence of a native z0live session. The actual Android z0live route must first be demonstrated and its exact code/build pinned. No experiment in this plan implies that integration already exists.

## 1. Measurement contract: what counts as audible

- **Trial unit:** one scripted turn plus its expected reply and all interruptions; **session unit:** one continuous phone voice connection spanning multiple trials. Repeated turns in the same session are correlated. A precondition failure is a scored failure, not a conveniently removed slow observation. Exclusions are limited to corrupted instrumentation proven independently of the arm, with counts/reasons retained.
- **Input EOS:** physical end of the final intentional voiced sample **at the phone microphone** (calibrated capture/cross-correlation against the injected fixture), not synthetic file EOF, model VAD event, transcription finalization, or app stop-record callback. Silent trailing padding does not extend EOS. Preserve separately: injection timestamp, acoustic arrival, Android capture timestamp, VAD/EOT timestamp, STT first/final, LLM start/first token, TTS first generated PCM.
- **First audible agent audio:** first sustained **agent** playback at the phone speaker/earpiece/headset coupler after EOS, recorded at the physical output probe. Score 20 ms windows; speech-active means ≥ −36 dBFS RMS over at least three consecutive windows (60 ms), with the event timestamp at the first window onset. Before scored trials, calibrate this detector per output route against ambient/noise floor and a reference synthetic voice; document deviations from PR #101's 50 ms / 0.015 RMS desktop detector. Do not count notification beeps, user stimulus bleed, silence, mere decoded PCM, or an LLM text token as agent speech.
- **Barge onset:** acoustic arrival of the first valid intentional user phoneme **while assistant playback has been active for ≥200 ms**. **Barge silence:** the start of the first 300 ms contiguous below-threshold agent-audio interval after onset, confirmed by both output probe and a floor/cancel event; differentiate true cancellation from a natural sentence pause by a positive interruption receipt and no old-turn resumption. If there is no qualifying active playback after a bounded 10 s attempt, the trial is a *failure to elicit assistant playback*, not a passing barge run.
- **Monotonic time:** within the external audio interface, source/reference and output/coupler channels share one sample clock (preferred; timestamps = sample index/sample rate). Phone monotonic timestamps use Android elapsed-realtime nanoseconds; host events use monotonic nanoseconds. For cross-device joins, repeat at least 20 timestamp exchanges before/after each session and fit offset **and clock drift** from minimum-RTT pairs; add start/end chirp calibration between source/reference tracks and phone mic capture. Log median and max calibration residual. Never subtract unsynchronized wall times.
- **Uncertainty rule:** source/output acoustic edge uncertainty must be ≤20 ms for primary latency analysis and ≤35 ms for Bluetooth; otherwise label TIMING_UNQUALIFIED and do not compute a passing p95. Bluetooth codec/coupler delay and packetized output are measured at the physical sink, not inferred from transport callbacks. Store uncertainty in each receipt.

### Proposed gates — thresholds are *hypotheses*, frozen before first pilot/scored phone run

| Metric (unit) | Exact observable / denominator | Proposed acceptance gate per arm, phone class and qualified route |
| --- | --- | --- |
| EOS → first audible p50 / p95 (ms) | Phone-mic acoustic EOS to physical output first agent voice; all eligible direct turns; report p50/p95/p99, failure count, and stage decomposition | p50 ≤ **1,500 ms**; p95 ≤ **2,500 ms**; challenger additionally ≤ matched hosted-control p50 + **150 ms** and p95 + **300 ms** |
| Barge → playback stop p50 / p95 (ms) | Acoustic user onset to persistent real acoustic silence; denominator all prompted barge opportunities, including no-stop/timeout as failures | p50 ≤ **200 ms**, p95 ≤ **500 ms** on built-in/wired route, ≤ **850 ms** on Bluetooth; ≥99% silenced in **1,000 ms**, zero stale-resume events; p50 ≤ matched control +100 ms |
| Missed user turn (%) | Valid synthetic utterances never acknowledged/acted upon by deadline 10 s after EOS; include mic/VAD/STT/drop/offline failures | ≤ **2%** per cell; never hide missing turns as unobserved data |
| Missed end of turn / late commit (%) | Speech reached client but no correct turn finalization by EOS +1,500 ms; denominator turns with validated audio capture | ≤ **2%**; report the continuous EOS→EOT delay (ms) and false end-of-turn split rate ≤2% |
| False interruptions (%) | Nonspeech-only injection causes speaking reply to stop, or triggers an unintended user turn; numerator corroborated by audio plus floor/VAD event; denominator controlled nonspeech probes | ≤ **1%** with ≥100 probes; separately report unexplained ≥300 ms natural pauses without mislabeling as interruptions |
| STT WER (%) | (substitutions + deletions + insertions)/reference word count for pinned exact prompt transcripts; aggregate edit counts over words, normalized lowercase/punctuation/Unicode/number style; silence insertions reported separately | ≤ **10%** clean and ≤ **20%** noisy across direct STT arms; report per accent/voice and p95 utterance WER; native speech-to-speech models with no accessible STT leg = **N/A, NOT zero** |
| Spoken-task oracle success (%) | Exact allowed mock state/action/answer within task deadline (10 s simple, 30 s multi-step); denominator all scripted tasks, including timeout and no response | ≥ **95%** overall; ≥ **90%** in every task family; consequential mock commands require 100% authority/confirmation fidelity |
| Wrong/duplicate/stale execution (count) | Mock action ledger and output speech provenance keyed to turn/command id; compare actual events with oracle, including after reconnect | **0** unauthorized, repeated, stale, or irreversible actions; any event is a blocking safety failure |
| Unsolicited/replayed speech (count) | Any unexplained agent utterance within 20 s after an explicit close, or output from an already cancelled turn | **0** in ≥100 closing/interrupt opportunities; interrupt follow-up correctness ≥98% |
| Session survival (%) | Fraction of predeclared 10-minute sessions reaching full duration without app crash, lost voice transport, unrecoverable audio route, or absent floor state; every start is denominator | ≥ **98%** (binomial denominator reported); screen-on baseline and each lifecycle condition separate |
| Screen-off/background, network-switch, Bluetooth route recovery (%, ms) | Fraction of scripted transitions returning to two-way audible dialogue within 5 s; report p50/p95 recovery from externally verified transition time, loss/reconnect count | ≥ **95%** of transitions; p95 recovery ≤ **5,000 ms**; zero duplicated tasks, forced mic recording without consent, or silent route mismatch |
| Battery drain (percentage-points/10 min; mWh/10 min) | Measure charge delta and, where exposed, integrated current×voltage energy for 10-minute warm-state sessions; subtract matched app-idle baseline; report battery temperature, OS measurement granularity and charging state | Gross ≤ **3.0 percentage-points/10 min** and excess above idle ≤ **2.0 percentage-points/10 min**; mWh also recorded (no cross-device universal mWh threshold) |
| Network data (MiB/10 min, KiB/turn) | Per-app UID transmitted+received bytes by Wi-Fi vs cellular before/after matched 10-minute sessions; include protocol overhead and reconnect traffic | Metered cellular ≤ **25 MiB/10 min**; offline arm must have **zero external media payload** in airplane-mode qualified run; report Wi-Fi separately |
| Attention dead air (ms) | Longest silence during a valid delegated response, from acknowledgment or EOS to verified audible outcome, with async worker status distinguished | p95 ≤ **10,000 ms** on short mock tasks; any pending task mislabeled as completed = blocking |
| Provider cost (USD/10 min) | Independently billed token/audio usage and exact price vintage if obtainable; no fabricated pricing | Report only until verified; no new metered spending beyond previously authorized hosted control |

These numerical thresholds are **proposals**, not measured SLOs or claims from prior work. The fixed non-inferiority margins above are inspired by the desktop parity gate in PR #101 but require explicit phone preregistration. Battery percentage-point readings over 10 minutes are coarse: qualify only after ≥120 minutes aggregate warm, unplugged measurements per arm/phone, and mark ENERGY_UNQUALIFIED if instrumentation resolution/counter drift exceeds the proposed margin. An arm cannot PASS while any required metric is N/A; characterize its valid features, then mark NOT_COMPARABLE or PARTIAL.

## 2. Hands-free harness / bench runbook (design only)

**Authority prerequisite:** a new, explicit approval is required before touching a physical phone, enabling accessibility/audio capture, changing Wi-Fi/cellular/Bluetooth, installing an app, making hosted calls, or recording anything. This plan is not that authorization. Test on a dedicated, consented device/profile; never use active personal sessions. No ADB/phone commands are run here.

1. **Freeze:** record one immutable Git commit for each source and adapter, binary hash, model checkpoint/version, fixture manifest hash, codec, sample rate, routing, OS/build *class* (no serial), power saver, app lifecycle settings, volume, mic gain, packet-loss profile, and provider pricing date. Use synthetic mock tools only, not live contacts, calendar, OS actions, agent terminals, or stored accounts. Require a deterministic mock executor that returns structured, independently verifiable receipts.
2. **Construct stimulus once:** synthesize all 32 below with a licensed/offline TTS voice (e.g., the Apache-2.0 Kokoro fixture method already used by PR #101); two voice variants at fixed pacing, sample rate, level (−20 dBFS active RMS; peak at most −1 dBFS), silence trim, and fixed RNG seeds. Create fan, keyboard, street-like noise **procedurally**, fixed SNR +10 dB and +0 dB. Hash *every* PCM/noise artifact and license metadata. No live speaker and no personally recorded voice.
3. **Fixed acoustic rig:** speaker plays the synthetic person to the phone mic at a marked position, approximately 30 cm away; room background target ≤35 dBA with calibrated meter, fixed speaker level and handset orientation. Primary route is phone built-in speaker; additional wired/Bluetooth headphones use calibrated ear-cup coupler. A two-channel external capture interface records (A) the synthetic-stimulus reference close to the phone mic and (B) physical phone output, on one hardware clock. Test echo/AEC with input and output simultaneously active. A virtual audio loopback can debug the pipeline but is *not* a substitute for real mobile microphone/speaker qualification.
4. **Drive with automation:** an already-approved, isolated debug-client control interface or consented device automation launches a seeded mock session, changes only allowed audio routes/network/lifecycle, injects the stimulus, schedules barge at detected output playback, queries mock receipts, and terminates the session. The runner never relies on an operator saying any line or grading responses.
5. **Calibrate:** record silence, one known speech calibration clip, source/playback offsets and 20+ time-sync exchanges at start/end; verify acoustic onset and EOS by waveform cross-correlation. Measure equipment noise, jitter, injected clipping, packet capture completeness and reference-coupler delay. Reject timing qualification if the uncertainty gate is missed; record every rejection.
6. **Warm-state discipline:** cold start and warm-state trials reported as separate cohorts. Randomize arm order in Latin-square blocks by phone class and condition; equalize idle time and volume. Run no personal background workloads or unrecorded model-download/setup during scored sessions. Mark any unavoidable host contention, thermal throttling, GC, OS killing, or network relay as stratification labels, not excluded anomalies.
7. **Exercise phone-specific transitions:** (A) screen on/foreground, (B) screen off for 10 min while recording consent/foreground-service state, (C) app background/foreground, (D) Wi-Fi → cellular mid-utterance and mid-assistant speech, (E) Bluetooth connect/disconnect during both listening and speaking, (F) cellular loss/restoration. Predeclared transition marker via external controller; stop if the OS revokes mic permissions. Screen-off/background may be OS-ineligible without a compliant foreground service; mark UNSUPPORTED, never work around system restrictions.
8. **Collect sanitized traces:** emit only monotonic offsets and event *types* keyed by random per-run IDs; stage timings (EOS, VAD, endpointer, STT partial/final, LLM first token, TTS first PCM, WebRTC send/receive jitter/packet loss where provided, physical first audible, barge stop), hashed fixture ID, anonymized hardware tier, OS/version class, app route, network type, audio route, mock oracle outcome, retry, cancellation and consent flags, battery counters, per-UID network bytes, error categories and timing confidence. Raw mic/playback waveform needed for calibration stays on a permissioned local test system and is deleted on policy-defined retention; public outputs are allowlisted aggregate summaries only.
9. **Prevent privacy leakage:** no transcript of a real person, raw account event, contacts, real location, call metadata, serial number, exact device ID, hostname, network address, token, private path, or full diagnostic log in Git. A deterministic allowlist-based exporter checks every field; strip provider/request IDs and PII-like tokens. References and transcripts are exactly the synthetic catalog, and only fixture hashes/aggregate WER cross the publication boundary. Pin sanitized evidence receipts by SHA-256 and place canonical media/fixture ownership in z0live, not a second z0evals copy.
10. **Audit and score offline:** join per-turn acoustic, synthetic prompt, and oracle events, flag absent stages, compute per-family and per-condition gates, bootstrap *whole session blocks* for confidence intervals, and export a manifest/scorecard suitable for #55's evidence wrapper. A separate grader reads only mock authoritative state and deterministic rules; model self-judgment never supplies the pass label. Publish FAIL, PARTIAL, NOT_COMPARABLE and incomplete outcomes too.

**Calibration failure example:** if a Bluetooth route changes the measured coupling latency or disconnects during recording, retain that failure in the survival denominator; do not transplant the earlier device's input/output time calibration or reinterpret host decoded PCM as physical audio. Synthetic-only headless replays can test event protocol but cannot clear any phone-acoustic threshold.

## 5. Minimum replication and analysis lock

1. **Smoke pilot** (not scored): all 32 utterances once per arm; only debug harness, calibration and missing fields. Freeze thresholds, audio hashes, oracle logic, statistical plan and eligible arm SHAs **before** scored sessions. Any post-hoc fix creates a new version and a new held-out confirmation cohort.
2. **Clean confirmation:** ≥10 independent shuffled repetitions of each of the 32 utterances per arm **per phone class** (≥320 prompted spoken turns), spread over ≥20 independent sessions and ≥2 test days. Same fixture/seed blocks across arms. Additional B21–B24 executions until each arm has ≥100 barge opportunities (not merely successful barge events), plus ≥100 silence/noise-only NEG probes and ≥100 closing/stale-speech opportunities. Failed starts, dropouts and timeouts stay in denominators.
3. **Lifecycle/stress confirmation:** ≥60 eligible transitions **of each** screen-off, background, Wi-Fi→cellular, and Bluetooth-connect/disconnect class per arm/phone; alternate mid-utterance and mid-playback. At least 60 uninterrupted 10-minute session attempts overall per arm/phone, balanced across foreground/background and radio types; for energy/data, ≥12 unplugged 10-minute warm-state observations per arm/phone, repeated across ≥2 days and paired with matching idle controls. If unsupported by OS policy, record UNSUPPORTED and block release claims for that condition.
4. **Held-out splits:** keep entire sessions, seeds, variant voices, calendar-day blocks and any retries of the same scenario together; use acquisition for debugging and independent confirm/OOD (different synthetic voice/SNR/audio route) for gates. No model, endpointing, noise threshold, prompt or grader tuning on confirm/OOD. Import only allowlisted aggregates into z0evals and preserve one immutable revision of fixture provenance.
5. **Statistics:** publish each arm's raw numerator/denominator, invalid-instrumentation count, p50/p95/p99 for applicable latencies with **session-cluster bootstrap 95% confidence intervals** (e.g., 10,000 seeded resamples), Wilson 95% interval for proportions, plus absolute and paired differences H→L and H→Y in the same blocks. Treat censored timeouts as failures and additionally show conservative latency bounds rather than dropping them. Report by route/device/condition; pair only like-for-like hardware/codec/acoustic measurement. An effect whose interval overlaps the non-inferiority margin is **INCONCLUSIVE**, not PASS. Never invent precision from correlated turns.

The exact n above is a *minimum feasibility requirement*, not an assertion of sufficient statistical power for a 1% failure rate. Zero failures in 100 opportunities is still compatible with a nonzero population risk: release approval requires independent owner judgment and #32 physical acceptance. Freeze a prospective power check using pilot **variance only** (not gate outcomes) before final confirmation if stricter inference is needed.

## 6. Selection and stop rules

**Entry gate:** the actual Android client/adapter exists, owner authorization covers its tests and service/provider use, all relevant recordings are synthetic, deterministic mock receipts work, clocks are qualified, and audio is observed at a physical output. Failing entry = NOT_COMPARABLE, not an inferred win. A headless replay PASS may support #55 but never by itself demonstrates real mobile-acoustic PASS.

**Blocking violations (stop immediately, preserve sanitized receipt):** unauthorized or duplicate mock side effect, false claim that a pending tool is done, stale/replayed speech after cancel/close, unexpectedly recorded personal audio, mic use after consent withdrawal, cross-route private audio exposure, OS restricted-background recording, or app instability that could compromise active phone use. One such event disqualifies the run and blocks promotion regardless of mean latency, WER, or cost. Do not tune safety gates after inspecting challenger failures.

**Default decision:** compare eligible H/L/Y on matched hardware, route and held-out confirmation. A challenger can replace the phone default only if **all absolute thresholds pass**, matched latency non-inferiority intervals satisfy the frozen margins, task/safety/lifecycle gates pass on both hardware classes, WER is qualified where relevant, no route is hidden as untested, and #32 owner-led physical-acoustic parity is separately approved. If multiple pass, use a **Pareto table**, not a blended score: prefer lower metered cost/data/battery and local control when the confidence intervals support a gain without exceeding +150 ms p50 / +300 ms p95 latency margins; otherwise retain H. Do not prefer a fast arm with worse missed-utterance, background survival or unauthorized-action rates. If H itself misses an absolute safety gate, **ship none** as a newly certified default; fix and retest.

**Evidence statuses:** KEEP = fully qualified and passed against the fixed baseline; DISCARD = hard safety failure or confirmed worse than margins; PARTIAL = valid scoped measurements with incomplete dimensions; NOT_COMPARABLE = distinct modality/route/model capability or unqualified physical conditions. PENDING/NOT_RUN is not a fifth kind of successful evidence. Result review/promotion belongs to z0intelligence; z0evals only freezes and reports, with independent review required.

## 7. Risks and mitigations

- **Android restrictions:** background microphone, audio focus, foreground services, permissions, privacy indicators, accessibility service state and thermal/doze behavior can change by OS/phone. Never bypass them or infer background success from a foreground run.
- **Echo/route confounds:** acoustic echo cancellation can eat the synthetic barge; Bluetooth codec buffering and route switching can add hundreds of milliseconds. Log actual physical route, device-side media stats and external coupler calibration; do not declare a fast first-audio result from a WebRTC decoded callback.
- **Clock and detector confounds:** mismatched clocks, 50 ms vs 20 ms detector windows, output natural pauses and source leakage alter measured timing. Publish threshold/calibration uncertainty and raw false-stop subcategories; use independent waveform and floor-event evidence.
- **Work/power/network confounds:** rate-limited hosted sessions, mutable provider versions, warm vs cold models, local GPU contention, server/phone energy separation, charging, radio signal and cellular quotas can make arms incomparable. Capture each separately and run blocked randomized sessions.
- **Synthetic-domain shift:** artificial prosody/accents and lab noise do not model natural user interruption, accessibility acoustics or fatigue. Include held-out TTS voices and SNR; label all findings synthetic, then seek separately consented human acceptance under #32 before defaulting.
- **Privacy, license, billing:** synthetic clips only; source TTS licensing pinned; no raw media/public tokens/addresses/IDs/private logs; provider speech transport may leave device; no extra cost beyond authorized control; source-owner retains raw fixtures.
- **False measurement confidence:** p95 with few events and coarse percentage battery readings cannot support strict conclusions. Use stated minimum n, confidence intervals, repeat days, and INCONCLUSIVE where underpowered.
