# GEPA reproduction-first preregistration — IFBench / Qwen3-8B

**Status:** preregistered, 2026-10-27. **Evidence class:** protocol only. No optimizer rollouts, inference, held-out evaluations, reproduced scores, or external spend have occurred. This document is not evidence that GEPA works on Zer0 routing. The primary goal is to reproduce a specific published number *before* transferring the method.

This is the work item in [z0evals #124](https://github.com/kvnloo/z0evals/issues/124). Credit: **Lakshya A. Agrawal and the GEPA coauthors**, *GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning*, [arXiv:2507.19457v2](https://arxiv.org/pdf/2507.19457v2). Distinguish **paper-reported** settings below from **our preregistered choices** and **unresolved fidelity gates**.

## 1. Target claim (one fixed paper row)

**Primary target:** paper **Table 1**, **IFBench**, **Qwen3-8B** (GEPA *without merge*), [paper PDF, Table 1](https://arxiv.org/pdf/2507.19457v2#page=8).

| Field | Paper-reported value |
| --- | --- |
| Benchmark / target model | IFBench / Qwen3-8B |
| Unoptimized baseline | **36.90** percent prompt-level accuracy |
| GEPA (no merge) | **38.61** percent prompt-level accuracy |
| Absolute advantage | **+1.71 percentage points** |
| Reported optimization evaluation budget | **3,593 rollouts / metric calls**, not tokens, candidate counts, or LM reflection requests |
| Paper's early-discovery observation | **678 rollouts** to discover the reported candidate; descriptive only, not the allocated stopping budget |
| Source | Table 1; methodology and IFBench experimental appendix of [the paper](https://arxiv.org/pdf/2507.19457v2) |

**Why this row:** Qwen3-8B is the smallest open-weight model explicitly available in this paper's IFBench comparisons and permits a low-cost hosted full-precision primary run. Quantized 8B inference may be explored on one 12 GB GPU, **but a 4-bit run is a separate feasibility study, not an exact paper reproduction**. The tiny reported +1.71-point improvement is a difficult, falsifiable target; no success is assumed. Do not substitute the paper's GEPA+Merge or a different benchmark/model row.

## 3. Data, splits, seeds, and licensing

**Paper-reported split design:** 150 training examples, 300 disjoint validation examples from IF-RLVR training/instruction-constraint material, and **294 held-out IFBench test examples**; GEPA updates against train, selects candidates using validation, and touches test once only after optimization. The paper evaluates unseen IFBench constraints; consult its IFBench methodology/appendix at [arXiv](https://arxiv.org/pdf/2507.19457v2#page=24). The published IFBench distribution provides **58 out-of-distribution test constraint types**, not an invitation to train on them.

**Source acquisition:** download `allenai/IF_multi_constraints_upto5` from [Hugging Face](https://huggingface.co/datasets/allenai/IF_multi_constraints_upto5) for construction of the paper's 150/300 dev partitions; download `allenai/IFBench_test` from [Hugging Face](https://huggingface.co/datasets/allenai/IFBench_test) or the pinned [`data/IFBench_test.jsonl`](https://github.com/allenai/IFBench/blob/1c40f0c10d9b5c5c2f10a175a28007ebb64f7f4d/data/IFBench_test.jsonl) for the 294 locked test cases. Use [IFBench evaluator `run_eval.py`](https://github.com/allenai/IFBench/blob/1c40f0c10d9b5c5c2f10a175a28007ebb64f7f4d/run_eval.py), checking **prompt-level loose accuracy** rather than replacing it with a per-constraint score. [IFBench README](https://github.com/allenai/IFBench/blob/1c40f0c10d9b5c5c2f10a175a28007ebb64f7f4d/README.md) specifies **Apache-2.0 for code, ODC-BY-1.0 for data**, and separate terms for some third-party-generated outputs; respect Ai2 responsible-use terms. Paper source and dataset distribution are different artifacts; do not assume the current dataset HEAD was the author's revision.

**Seeds and immutable splits:** the paper's exact IFBench 150/300 row IDs, row-ordering/sampling seed, and original model/reflection checkpoint revisions are **not verifiable from the cited public configuration**. The optimizer `seed=0` above is **our preregistered run choice, not an author-reported seed**. Before a paper-exact run, recover original example IDs or published split-generating script + immutable dataset revision, verify disjoint IDs and `150 + 300 + 294`, and freeze a cryptographic ID/hash list and all model/data/repo SHA values in the operator's private run receipt. If source partitions remain unrecoverable, the only permissible run is separately labeled **method replication**, with a frozen `seed=0` split determined *without reading test answers*; it cannot earn a paper-exact PASS. No random-row reshuffle after observing scores.

## 4. Tolerance and locked verdict decision tree

Use **percentage points** (not relative percent); score is `100 * mean(prompt_level_loose_pass)` on the same locked 294 examples. A single observed paper row has no published IFBench per-seed variance in the accessible source. **Our predeclared ±3.00 pp tolerance** is pragmatic, approximately one simple-binomial standard error for `p=0.3861, n=294` (`sqrt(p(1-p)/294) * 100 ≈ 2.84` pp), **not** a reported confidence interval, proof of equivalence, or a post-hoc fit.

- **PASS:** all pin/split/model/evaluator/fidelity gates satisfied, `33.90 ≤ baseline_score ≤ 39.90`, `35.61 ≤ GEPA_score ≤ 41.61`, `GEPA_score - paired_baseline_score > 0.00` pp, optimizer total metric calls `≤3593`, and no safety/verifier tampering. Cite exact source commit, row hashes, scorer, run receipts, and actual costs.
- **FAIL:** experiment valid with full 294 held-out rows, but `GEPA_score <35.61` or `>41.61`, or `GEPA_score ≤ paired_baseline_score`, or baseline outside `[33.90,39.90]` while settings were otherwise paper-identical. A too-good score does not silently count as faithful reproduction.
- **INCONCLUSIVE:** infrastructure stop, missing full sample due to outage, failed deployment preflight, unrecovered original reflection LM or author split before spending, or uncertain scorer interpretation; publish reasons and any partial accounting, but **no numerical PASS/FAIL**. A 95% paired bootstrap CI of GEPA-minus-baseline spanning zero is reported as uncertainty alongside the deterministic verdict, not hidden.
- **INVALID (cannot count toward the primary paper claim):** either pinned package SHA mismatch, non-original data or partition, test leakage, different model weights or quantization, changed evaluator or decoding, paper optimizer setting change, optimizer >**3593** calls, held-out evaluations >**588** program calls (294 per arm), or aggregate >**4181** optimizer-plus-final-test program calls; quarantine these observations as separate ablations, never retroactively relax a gate.

For precedence, **INVALID** overrides scores; otherwise **INCONCLUSIVE** for incomplete/unresolvable runs; then **PASS/FAIL** from thresholds. All 294 held-out example IDs must be identical for paired baseline/GEPA. No adaptive tolerance, metric, or seed changes after looking at final-test outcomes.

## 5. Budget, hosted/local cost model, hard stops

**Optimizer cap = 3,593 program-evaluation/metric calls**; each example uses **two sequential Qwen3-8B predictor generations** (up to about **7,186** task generations for optimizer calls), plus at most **294 baseline + 294 GEPA** final test program evaluations (**1,176** more task generations). The reflection model adds separate charged LM calls; the paper's reported reflection-call count is descriptive, **not** another rollout counter. Log *physical* LM calls/tokens, retries, cache hits, context overflow, and generation settings; no free hidden provider calls. Baseline must receive exactly the same inference settings and independent test queries.

## 7. Threats to validity and countermeasures

- **Contamination:** model pretraining may contain IFBench tests; prevent train/dev/test IDs and paraphrases from crossing folds, hash and semantic-dedup data, preserve all prompt lineage, and disclose unverifiable model pretraining exposure.
- **Seed/sample variance:** author IFBench seed and exact 150/300 IDs currently unverified; `seed=0` is our protocol choice. Report complete row hashes, optimizer RNG, decoding seed if supported, and paired 294-row differences; never infer a multi-seed variance from one paper result.
- **Reflection leakage:** separate reflection from the locked test dataset, bar test outputs/verifier gold and score tables from reflection context, and ledger all context sent to any hosted service. Paper's reflection-model identity is a fidelity gate, not a detail to silently guess.
- **Prompt-length drift:** GEPA may increase tokens/cost/context overflow; freeze 16,384 context policy, track actual tokens and truncation for each stage, fail if a provider applies unlogged prompt truncation. Any different max output or tokenizer is a separate arm.
- **Evaluation mismatch:** IFBench strict vs loose metrics, prompt-level vs constraint-level aggregation, stale verifier versions, Qwen thinking mode, model revision, sampling temperature, and caching each change the claim; pin and report.
- **Selection bias:** valset chooses the prompt; test is one-shot; stop if a failed attempt induces adaptive edits or if runs share test feedback. Keep failures rather than picking best seed.
- **Budget accounting:** DSPy metric calls are *program* evals, not physical LM calls or reflection calls; report both. Frozen optimizer budget and a separate complete cost ledger are required.
